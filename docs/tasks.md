## P1-1. Push-уведомления (обязательно)

**Проблема:** ни библиотеки, ни flow; в `package.json` ничего для пуша нет. Сценарии: статусы заказов (создан → подтверждён → в пути → доставлен), акции/промо.

**Что сделать:**

1. Выбрать стек:
   - Классика: `react-native-push-notification` + FCM (`@react-native-firebase/messaging`) или `notifee` (локальные + красивый рендер).
   - Android 13+: runtime permission `POST_NOTIFICATIONS`.
   - iOS: APNs + `userNotificationCenter`.
2. Уведомления по статусам заказа: при клике — deep link на `OrderDetail` (для этого понадобится связка: в заказе должен быть id; в навигации `OrderDetail` уже есть в `BasketStack`/`ProfileStack`, добавить в root при необходимости).
3. Бек: отправка device/registration token (`/devices` или подобный эндпоинт — уточнить), отправка пуша при смене статуса.
4. Локальный fallback: т.к. FCM требует настройки Firebase (google-services.json / GoogleService-Info.plist), можно начать с локальных уведомлений `notifee` и расширить позже.

**Проверка:** [ ] токен устройства уходит на бек, [ ] локальные уведомления работают (андроид/iOS), [ ] deep link открывает заказ, [ ] permission flow, [ ] `lint` + `tsc`.

## F-1. Зоны доставки на карте

**Требование (пользователь):** при оформлении доставки курьером нельзя выбирать любую точку — нужно рисовать зону доставки на карте. Параметры зон делаются на беке: у складов — радиус/полигон покрытия и стоимость (дальше от склада — дороже). Зоны настраиваются в админке, фронт динамически получает доступные зоны.

**Текущее состояние:** `CheckoutScreen` получает склады (`fetchWarehouses`, `CheckoutScreen.tsx:60`), карту рисует `src/screen/Checkout/components/map/MapBox.tsx` (`@rnmapbox/maps` v10.3.5). Сейчас можно выбрать любую точку; стоимость доставки фиксированная — `delivery_price = method_receipt === "courier" ? 100 : 0` (`CheckoutFooter.tsx:77`).

**Что сделать:**

1. **API (бек):** новый эндпоинт зон доставки (например `warehouse/zones` или поле в структуре склада): геометрия (полигон `GeoJSON` / центр + радиус), стоимость доставки по зоне, расписание. Уточнить модель данных в `src/shared/types/warehouse.ts` и `AddressItem`.
2. **Фронт — отрисовка зон:** в `MapBox.tsx` добавить `FillLayer`/`ShapeSource` с полигонами зон (или круг радиуса), подсветка зон, кликабельная область; при выборе точки не из зоны — блокировать выбор и показывать сообщение.
3. **Расчёт стоимости:** выбор зоны → `delivery_price` из зоны, отображение в `OrderSummary` и `CheckoutFooter` вместо фиксированных 100 ₽; учесть в `CreateOrderPayload`.
4. **Динамика:** подгрузка зон при входе в чекаут и при смене склада/способа получения; санитайзинг данных (зоны обновляются в админке).

**НЮАНС — карта не собирается под Android (блокер, исследовать в первую очередь):**

- Текущая: `@rnmapbox/maps`. Проблема: «не могу сбилдить под андроид с этой картой».
- Диагностика: версия `10.3.5` vs совместимость с React Native 0.87/Gradle; скачивание SDK-артефактов (Mapbox приватный репозиторий требует токен/регион); `MAPBOX_ACCESS_TOKEN` для Android (лимиты загрузки тайлов); network security / NDK / Java версия.
- Варианты замены (если не чинится): `react-native-maps` (Google Maps / Apple Maps), **MapLibre** (`@maplibre/maplibre-react-native` — drop-in замена Mapbox, без токенов) или web-view карта (хуже опыт). Выбор — отдельным прототипом: собрать минимальный Android build с каждой.
- Итог задачи: сначала прототип карты под Android, затем зоны доставки.

**Проверка:** [ ] aндроид-сборка с картой работает, [ ] зоны рисуются, [ ] выбор точки вне зоны заблокирован, [ ] стоимость зависит от зоны, [ ] `lint` + `tsc` + `jest`.
